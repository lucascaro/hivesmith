- **Brain lookups no longer let untrusted text run shell commands.** Nine skills told the agent to "quote the terms" from issue or idea text before passing them to `brain-search`, and showed the command with double quotes (or, in `/brain-ask`, no quotes at all) — neither stops `$(…)` or backticks from executing. Every call site now says to reduce the terms to letters, digits, spaces, hyphens, dots and underscores and wrap them in single quotes. Dots and underscores stay, so identifier terms like `SKILL.md` or `create_issues` still match; only shell metacharacters are dropped. Affects `/feature-new`, `/feature-implement`, `/feature-triage`, `/feature-research`, `/feature-plan`, `/feature-loop`, `/brainstorm`, `/pr-queue` and `/brain-ask`.
- **Skills stop pointing at commands that don't exist on a default install.** `/brain-promote`, `/brain-garden`, `/brain-ask`, `/hivesmith-init`, `/graphify-init` and the brain templates hardcoded `/hs-`-prefixed command names, but the install prefix is empty by default. They now use bare names, which the installer re-prefixes in `SKILL.md` when `--prefix` is set. Golden principle #5's check, which could never pass because it matched the `hs-metric` emitter path, now matches only real skill names and runs in CI.
- **`hs-metric` accepts `checks=SKIP` on `autofix_applied`.** `/autofix` now skips its checks step when it applied no fixes — nothing changed on disk — as well as when `AGENTS.md` is absent, and reports `SKIP`. The emitter previously rejected that value, forcing the event to be dropped or recorded as a false `PASS`.
