- **The plan approval button now actually advances the loop.** `skills/plan-html/start.sh` is non-blocking by design and the canonical call sequence said only "poll `<plan>.approved.json`" — prose with no mechanism behind it. The agent rendered the plan, printed the URL, and its turn ended; the operator clicked Approve, the server wrote the file, and nobody was listening, while the page disabled the button and displayed "✓ Approved". A new `skills/plan-html/wait.sh` is the missing wait: it blocks and returns `0` on approval, `10` once per-section feedback has settled (an 8s quiet period, because the page autosaves on a 1.2s debounce and returning on the first keystroke would yank the plan away mid-sentence), `11` on timeout so the caller loops within the harness's bounded Bash timeout, and `3` if the server died. `start.sh` now also reaps a predecessor server for the same plan and clears stale `.approved.json` / `.feedback.json` sidecars — a re-run on the same slug used to inherit the previous run's approval and advance instantly, before the operator had seen the page.
- **`hs-metric` — a schema-validated event stream for the pipeline.** The loop already produced structured data at four points (the plan second opinion, review-loop's per-iteration envelope, merge-gate's per-dimension verdict, review-pr's findings) and dissolved every one into markdown prose. `scripts/metrics/emit.sh` appends one JSON line per event to `${HIVESMITH_HOME:-~/.hivesmith}/telemetry/pipeline-events.jsonl` and **fails loudly**: unknown event, missing required field, unknown field, wrong type, or out-of-enum value all exit 64 and append nothing. Unknown fields are rejected on purpose — a free-text escape hatch is how structured data decays back into prose. Second opinions are now recorded once per round, so a `revise` that later flips to `approve` is distinguishable from a first-pass `approve`; the plan section only ever kept the final verdict.
- **Regressions are declared, not inferred.** `.changesets/*.md` gains an optional `regression_of: <PR>` field on `type: fixed`, filled by `/changelog-update` from the recent merged PR subjects it can actually check, and format-validated in CI (never validated for absence — omitting it is always allowed, guessing never is). `scripts/metrics/regressions.py` recovers declarations from `git log --diff-filter=A -- .changesets/`, because `release.sh` deletes those files and a working-tree scan would silently report zero forever after the next release. It reports Regressed / Clean / Unobserved as three distinct counts and never prints a bare regression rate, so a PR merged yesterday is never counted as clean.
- **Reporting, backfill, and CI coverage.** `scripts/metrics/report.py` merges the git-derived and locally-emitted tiers and prints the second-opinion cost/yield with its correlational disclaimer inline — there is no holdout arm, so nothing claims the reviewer prevented anything. `scripts/metrics/backfill.py` seeds history from existing `## Gate verdict` (and legacy `## QA verdict`) and `## PR convergence ledger` sections; every backfilled row is marked and quarantined from duration statistics, and pre-enum entries are named rather than mapped onto a nearest guess. A new `script-suites` CI job runs the three new test suites **and the eight telemetry/harvest suites that had no CI job at all**. Telemetry hooks stay opt-in: `install.sh` now reports their state in `--doctor` and `/hivesmith-init` offers a per-repo opt-in writing to `.claude/settings.local.json`, never the committed `settings.json`.
