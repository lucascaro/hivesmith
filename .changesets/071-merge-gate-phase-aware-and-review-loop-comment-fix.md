- **Merge gate no longer marks a phased feature DONE on its first phase** — exec plans gain an optional `Phase: N of M` header field. While `N < M`, `/merge-gate` records a per-phase PASS in `## Gate verdict` (carrying `phase: N/M`) and refuses the DONE bookkeeping entirely: no `Status: completed`, no move to `completed/`, no `pr:`/`shipped:`, no `stage: DONE`. It still commits and pushes the verdict, so the next gate or review-loop run does not refuse on a dirty tree. Plans that declare no phase are unaffected. Starting phase N+1 is a documented manual reset (`stage: IMPLEMENT`, bump `Phase:`, clear the plan's `PR:`/`Branch:`), and `/feature-loop`'s Phase 5 step 37 no longer force-advances a non-final plan back to `GATE`, which previously would have undone that reset. The `gate_verdict` metric accepts an optional `phase` field so a phase PASS is distinguishable from a full PASS.
- **`/review-loop` no longer contradicts itself on `COMMENT`** — its Philosophy said the loop ends on "`COMMENT` with only MINOR remaining" while its step 5 stopped on any `COMMENT` with strict off and zero open threads, so a `COMMENT` carrying IMPORTANT findings could end the loop with real bugs standing. All three statements now agree: stop only with strict mode off, zero unresolved threads, and an empty `findings_hash` (no BLOCKING or IMPORTANT findings). The check lives in the worker's pre-autofix decision so the hash and thread count describe one snapshot. `/merge-gate`'s cold-start guard is deliberately **not** tightened to match — ledgers written under the old rule record `action: stop` with a non-empty hash, and tightening would retroactively refuse them.
- **Documented how to resume a review loop that died mid-iteration** — a `## PR convergence ledger` whose last entry is `action: autofix+push` means a previous run pushed a fix and died before re-reviewing. `/review-loop`'s cold-start section now states that re-running the loop on the same PR is the recovery, and why it is safe.
