- **`regenerate-generated` now opens a PR instead of direct-pushing to `main`.** The job had been failing on every push to `main` since May: a protected branch rejects bot pushes outright (`GH006: Changes must be made through a pull request`, plus `3 of 3 required status checks are expected`), so the aggregates it regenerated were never landing and `CHANGELOG.md` drifted 31 lines behind `.changesets/`. It now commits to a `chore/regen-aggregates` branch, opens a PR labelled `regen-override` + `no-changeset` (force-pushing to update the PR in place if one is already open), and enables auto-merge. The loop terminates: merging the regen PR re-triggers the job, and the second run finds nothing to regenerate. Repos that keep `main` unprotected are unaffected in outcome — the change lands either way, just via a squash-merged PR.
- **Set a `REGEN_TOKEN` secret to make the path fully unattended.** With the default `GITHUB_TOKEN`, a PR the workflow opens gets its checks in an [approval-required state](https://docs.github.com/en/actions/using-workflows/triggering-a-workflow), so auto-merge parks until someone clicks "Approve and run". A non-admin PAT with contents + pull-requests write, stored as `REGEN_TOKEN`, removes that click; the workflow falls back to `GITHUB_TOKEN` when the secret is absent, so no configuration is required to adopt this.
